# 篮球进球检测视频最小闭环

用户已确认：复用 E:/basketball-highlight-editor 中的算法，在当前 worktree 独立实现；输入视频，返回带进球判定标注的完整视频。视频路径由用户自行配置，默认留空。

## 范围

- Python 命令行和 JSON 配置文件；命令行参数优先，配置中的相对路径相对于配置文件目录。
- 固定机位、单个篮筐；自动定位篮筐，支持可选手动 ROI。
- 复用球筐检测、候选生成、原视频精扫和逐帧穿筐复核。
- 输出 H.264 MP4，保留原视频有效时长及原音频；无音频输入也能导出。
- 画面显示篮筐、可用检测点与短轨迹、事件判定及累计确认进球数。轨迹缺失时不虚构检测框。
- 三类结果：进球、未进、无法确认。非事件时显示检测状态，不显示“未进”。事件前后短时间显示判定，时间范围限制在视频内；离线结果可标回事件时刻。
- 附带 events.json 和分阶段耗时，记录未确认原因；无进球仍返回带状态标注的完整视频。
- 不包含微信、任务队列、数据库、集锦剪辑、训练新模型。

## 路线

考虑过包装整个桌面 Engine、提取最小算法、重新实现检测三种方案。用户选择提取最小算法，以减少 GUI、SQLite 和人工审核流程依赖。保留上游 MIT 许可和来源记录，权重使用显式外部路径，不打包分发。

## 组件

vendor/basketball_highlight 与 vendor/scripts 保存选定的算法及脚本快照；basketball_detect 提供配置、流水线、判定适配与视频渲染。首版通过受控子进程调用脚本，参数使用列表传递，保留每阶段日志和中间 JSON；随后按需要优化模型重复加载。

使用原视频直接粗扫和精扫，首版省去代理视频与坐标缩放，先保证原图坐标和时间一致。粗扫建议 10fps，精扫默认 30fps、实际不超过源视频有效帧率，逐帧复核读取原始帧。参数均保存到运行报告。此项为实现建议，非实测最优值。

## 判定

读取 verdict 而非 state 判断；state=confirmed 并不代表进球。复核明确 made、精扫 verdict=made 且无反证时才自动计数；任一阶段证据矛盾或复核缺失则无法确认。只有明确反弹、侧向离开等反证才标未进。按上游去重逻辑合并同事件，保存原始证据供检查。三类结果只涵盖被提出的候选，不宣称能识别全部投篮尝试。

## 配置与失败

config.example.json 的 video 留空；model 指向用户已有模型；output 指向本项目 runs。空输入、路径不存在、模型不可用、未找到篮筐、解码失败、FFmpeg 失败均返回明确错误和非零退出码，不发布残缺成品。禁止输出覆盖原片；每次运行独立目录，成品校验成功后再发布路径。

## 验证

测试参数优先级、事件三分类、重复计数、时间边界、坐标与帧选择。用生成的视频及注入检测结果测试标注和音视频导出；此测试不能证明模型准确率。当前无用户验收视频，真实视频精确率、召回率及现场效果待配置视频后验收，不能以合成素材替代。
