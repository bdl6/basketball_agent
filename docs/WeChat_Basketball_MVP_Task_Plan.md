# 篮球进球剪辑助手：网页 Agent MVP 任务计划

版本：v0.3
日期：2026-11-26
用途：路线 B 可交互网页 Agent 的最终交付范围、任务拆分与验收依据。本文取代 v0.2 的纯任务编排方案及原微信小文件版计划。

## 1. 首版目标

构建基于 LangGraph + LLM 的可交互篮球剪辑 Agent。用户通过浏览器上传视频，系统自动识别可靠进球并生成集锦；用户通过自然语言调整剪辑，Agent 理解指令、调用受约束的工具，复用识别结果并生成新版集锦。网页提供处理状态、候选确认、播放与下载，刷新后可以恢复任务和待确认交互。

最终核心验收场景：上传视频 → 自动生成集锦 → 输入“去掉第二球，每球前面多留三秒” → Agent 展示修改内容 → 复用已有识别结果生成新版集锦。必须验证第二个事件已排除、其余事件前置时长相对原方案增加三秒、源视频边界正确，且没有重新执行识别。

优先验证固定机位、单个清晰篮筐的短视频。复用现有 Basketball Highlight Editor 的 Python 识别流程和 FFmpeg；项目代码和模型权重是否可获得、能否直接复用需先核实。微信客服回调服务属于已完成的历史探索，不纳入本版依赖和验收，也不删除既有代码。

## 2. 范围与边界

包含网页上传、任务创建与状态查询、后台队列、视频校验、自动识别与剪辑、LangGraph 编排与持久化、LLM 结构化指令与工具调用、自然语言修改、方案版本、局部重新执行、候选确认、网页播放和下载、错误反馈、文件清理，以及任务访问隔离。支持格式、大小、时长上限由服务器和浏览器实测确定，前后端使用同一配置并在提交前提示；不沿用微信限制。

首版语言操作支持：初始剪辑要求、设置或调整每球前后保留时长、排除指定事件、查询进度、根据更新后的方案生成新版。明确的修改指令可执行；语义有歧义时先澄清，不猜测执行。不支持的操作明确提示。

首版以短视频、单机任务和普通上传为起点；分块上传、断点续传、数 GB 整场录像和对象存储作为后续扩展，未承诺首版支持。包含简化的候选确认界面，不包含独立专业审核后台。微信、小程序、Flutter、球员识别、多篮筐和频繁切镜头暂不包含。完整录像需求保留于后续版本，不以旧 PRD 的 5 GB 指标作为当前验收承诺。

## 3. 用户流程

1. 打开网页，选择视频并查看格式和大小要求。
2. 上传时显示进度；服务端完成接收和校验后创建或确认任务。
3. 页面展示排队、分析、剪辑等阶段，刷新后可凭受保护的任务访问凭证继续查询。
4. 成功后在页面播放并下载集锦；下载失败时可在保留期内重试。
5. 无可靠进球、无法定位篮筐、格式不支持或处理失败时显示明确原因，不生成空视频。
6. 到期后清理原片、中间文件及成片，页面明确提示结果过期。

交互补充：用户可在上传时输入初始要求，未填写使用默认参数。成功后显示稳定事件编号、片段列表和方案版本；用户输入修改指令，Agent 展示理解后的变更，保存新版方案并异步渲染，新版本成功前保留旧版可用成片。不确定候选展示时间点、短片及证据，用户可确认纳入、排除或跳过；未确认者默认不纳入，不阻塞其他确认进球的初始交付，后续确认产生新版本。

## 4. 任务与验收

| 编号 | 任务 | 工作与验收 |
|---|---|---|
| T1 | 网页上传和原样交付 | 上传视频、校验并隔离保存，显示上传进度；结果页播放和下载同一文件；刷新后凭访问凭证继续访问。 |
| T2 | 引擎基线 | 找到现有引擎、依赖、模型和授权；用目标录像记录候选、误检、漏检、耗时和设备。 |
| T3 | 无界面封装 | 明确输入、区域、参数和事件输出；命令行完成识别及剪辑，产生有效 MP4。 |
| T4 | 后台任务 | SQLite 保存任务、独立 worker 异步处理；页面轮询状态，异常可查询；重启后的中断任务明确标记或恢复。 |
| T5 | 固定片段剪辑 | 以 FFmpeg 截取前 10 秒，短于 10 秒取有效范围；页面播放下载，提交请求不等待剪辑。 |
| T6 | 自动集锦 | 接入复核通过的事件、合并重叠区间、按时间顺序输出；无可靠进球时给出明确反馈。 |
| T7 | 隔离与清理 | 校验文件、限制上传及磁盘使用、随机任务凭证和受控文件访问、重复提交处理、有限重试、到期清理；双用户不能互相查看或下载。 |
| T8 | 端到端验收 | 在目标浏览器测试上传、刷新查询、播放、下载及异常；形成含样本、设备和时延的记录。 |
| T9 | LangGraph 主流程 | 显式节点、条件分支、持久化检查点与工具执行记录；服务重启可恢复，避免重复执行和发布。 |
| T10 | LLM 交互与方案版本 | 初始要求、前后时长调整、排除指定事件、查询进度；结构化校验、歧义澄清、不可变方案版本；修改时复用识别结果。 |
| T11 | 候选确认与恢复 | 展示候选证据，确认/排除/跳过；人工分支暂停恢复，刷新及重启后可继续，等待时释放 worker；无人确认不阻塞初始交付。 |
| T12 | Agent 端到端验收 | 通过第 1 节核心场景，验证局部执行、重复指令、版本冲突、模型故障、人工确认恢复和双用户隔离。 |

实施顺序：先核实 T2 引擎与样本，同时推进 T1 网页交付；完成 T3/T4/T5 工具与队列基础，再接入 T6 自动集锦、T9 图编排、T10 语言交互及 T11 候选确认。T7 隔离和资源限制从上传阶段开始实施；T8/T12 集中验收。M1—M3 为中间成果，最终交付必须完成 M4。

## 5. 识别与剪辑

优先验证现有 YOLO、轨迹、篮网运动和穿筐复核能力；自动定位篮筐失败时明确反馈。只将有证据支持的确认进球纳入集锦，不把未被排除的候选直接视为确认；保留不确定事件供后台误差分析。是否采用代理视频、精扫和其他复核方式，以现有引擎能力和基线实验决定。

以进球时间为中心，默认前 5 秒、后 2 秒，作为可配置初值；限制在源视频范围内，合并重叠区间，按时间排序，从原片导出浏览器可播放的 MP4。记录无音轨、源编码和浏览器兼容性，实际编码和画质以测试确定。

事件使用稳定 ID，方案保存所选事件、前后时长、输入和分析版本。网页区分事件与合并后的输出片段；“第二球”指当前展示方案按时间排序的第二个事件，不等同于第二个合并片段，指代不清先澄清。“多留三秒”为相对调整，“改成八秒”为绝对设置；重复提交同一操作不得重复累加。人工纳入的不确定候选记录来源，不计为模型自动确认正确。

## 6. 路线 B 技术方案

- 前端：React + TypeScript + Vite，提供上传、交互消息、进度、候选确认、事件列表、版本切换与播放下载。
- Agent 编排：LangGraph，负责显式状态、条件分支、工具节点、人工中断及检查点恢复。
- 语言理解：支持工具调用和结构化输出的 LLM；理解需求、澄清歧义、生成受约束操作并解释执行结果。供应商、型号、预算和超时在接入前确定，密钥只保存在服务端。
- LangChain：按需用于模型及工具适配，不作为强制依赖。
- 服务端：Python + FastAPI，提供上传、任务状态及受控结果访问接口。
- 异步处理：独立 worker 与任务队列，初期单机执行；SQLite 记录任务和事件。
- 识别：YOLO、OpenCV、NumPy，以及适配服务器的 PyTorch 或 ONNX Runtime。
- 剪辑：FFmpeg、FFprobe；每个任务独立目录，先使用服务器本地存储。
- 部署：本地先跑通，再部署目标服务器；外部访问、HTTPS、上传限制按部署环境实测。

部署采用 Docker Compose，持久化业务数据库、图检查点和视频目录。LangGraph 运行于后台执行体系，不替代独立 worker 和持久化队列。队列通过事务领取任务，配合心跳、超时和有限重试。

LLM 负责理解需求和调用允许的工具，视觉引擎负责识别证据，FFmpeg 负责实际剪辑。禁止模型直接执行 shell、拼接任意 FFmpeg 命令或凭文本臆测进球。默认向 LLM 发送必要文本和结构化元数据；向第三方发送视频或候选图像需另行明确数据边界。

### 6.1 工具与执行契约

| 工具 | 职责与限制 |
|---|---|
| analyze_video | 接收授权视频引用及分析参数，输出稳定事件 ID、源时间戳、判断类别、证据和引擎版本，结果可复用。 |
| list_events | 查询当前任务事件及确认状态，不能访问其他任务。 |
| update_edit_plan | 接收基础版本、操作 ID、事件 ID 和参数，经校验后保存不可变的新方案版本。 |
| render_highlights | 按已保存方案版本提交后台渲染并返回执行 ID，不在请求中等待编码。 |
| get_job_status | 返回真实阶段、版本、错误与产物可用性，不由模型编造进度。 |

所有工具统一经过参数、权限和幂等校验。模型传入的任务 ID、事件 ID 或路径不能绕过权限；人工确认必须来自鉴权后的用户操作。

### 6.2 图流程与局部重新执行

首次生成：解析初始要求 → 校验参数 → 分析 → 复核 → 建立方案 → 渲染 → 验证产物 → 交付。

修改：解析指令 → 检查事件与基础版本 → 必要时澄清 → 保存新版方案 → 复用分析结果渲染 → 验证并发布。修改时长、排除事件和确认已有候选均不重新识别。

人工分支：保存候选与检查点 → 暂停等待用户 → 鉴权并校验操作 → 恢复分支并更新方案。确认进球的初始交付不依赖未回复候选。暂停时释放执行资源，刷新或重启后仍可继续。

图状态仅保存文件和事件引用、版本与控制信息，不保存视频二进制。采用 LangGraph 持久化检查点，初期 SQLite 后端；业务数据库是网页状态和产物的事实来源，检查点负责恢复位置，通过幂等执行记录协调两者。业务任务 ID 与图会话关联，图会话 ID 不是访问凭证。

## 7. 任务状态与安全

上传与处理分开记录：uploading → validating → queued → analyzing → editing → ready；任一阶段可进入 failed，结果到期进入 expired。下载是独立操作，失败不重新识别。保存任务 ID、访问凭证的安全校验信息、输入元数据、阶段、事件证据、错误、输出路径和时间戳；日志不记录访问凭证。短时随机凭证与任务绑定，输入、状态、播放及下载均需校验权限，文件路径不直接公开。保留时间、上传上限及并发数在部署前配置并明确告知用户。

Agent 补充状态包括 reviewing、awaiting_confirmation 和 awaiting_clarification。处理状态按执行记录保存；等待确认是分支状态，旧版成片可用性单独记录，不能因新执行而覆盖。过期任务禁止继续工具调用。

保存对话、结构化操作、分析版本、方案版本、执行 ID、图检查点关联和产物引用。交互、候选与恢复接口均需鉴权，播放定位及下载的每次文件请求也需校验权限。对话、候选材料和检查点纳入保留期清理，日志不记录模型密钥。

操作 ID 防止重复修改，基础版本防止并发覆盖，版本冲突提示刷新。临时产物验证成功后才发布；新版失败保留旧版。worker 通过心跳/租约识别中断，按节点能力恢复或明确失败，重启不等于成功。模型瞬时故障有限重试，参数错误、无进球或格式不支持不盲目重试；模型故障仍可直接查询任务和下载已有成片。配置模型调用预算；清理全部版本和临时文件时避开活动执行。

## 8. 四个里程碑

### M1：网页原样上传、播放与下载

完成网页上传、服务端存储、任务查询、受控播放与下载。验收：浏览器上传短视频后，在同一任务页播放并下载原文件；刷新后可恢复访问，其他用户无法访问。此阶段不要求进球识别。

### M2：网页固定片段剪辑

引入后台队列和 FFmpeg，截取前 10 秒，展示阶段并交付结果。验收：短视频边界正确，刷新后状态可查，页面可播放下载，处理不阻塞上传请求。

### M3：自动进球集锦

接入已验证的识别与复核，生成按时间排序的集锦，补齐无进球、错误反馈与清理。验收：目标视频端到端完成，记录误检、漏检及耗时；无可靠进球或处理失败时反馈明确。

### M4：可交互 LangGraph Agent（最终交付）

完成 T9—T12，以及完整的隔离、清理和异常验收。必须通过第 1 节自然语言修改场景：理解并展示变更、保存新方案、复用识别结果生成可播放下载的新版。支持调整前后时长、排除事件、查询进度、歧义澄清和候选确认。

验收还需覆盖刷新及重启后恢复待确认交互、重复指令不重复生效、版本冲突不覆盖、新版失败保留旧版、模型故障后可重试，以及双用户无法访问彼此状态、对话、候选、检查点和产物。交付可运行项目、配置与部署说明、使用说明及验收记录。M1—M3 仅为中间成果，未完成 M4 不视为路线 B 交付完成。

## 9. 验收样本与指标

样本覆盖清晰进球、未进、遮挡、不确定、无篮筐、无进球、损坏文件、超限、重复提交、任务中断、下载失败和双用户隔离。记录进球精确率、召回率、片段完整性、上传和各处理阶段耗时、端到端成功率、输出可播放性和文件大小。准确率及性能目标待基线实验后确定。

Agent 用例额外覆盖初始要求、绝对/相对时长调整、事件与合并片段指代、删除事件、歧义、不支持要求、非法参数、伪造任务/事件 ID、重复操作、并发版本冲突、模型超时和人工确认恢复。记录指令与实际方案是否一致、工具调用正确性、重复识别次数、暂停恢复结果、LLM 调用量及费用。自动识别指标与人工纳入结果分开报告。核心功能按明确用例逐项通过，性能和费用目标由基线确定。

## 10. 待确认与历史资料

- 已确定路线 B：LangGraph + LLM 交互、工具调用、方案版本、局部重新执行和候选确认，M4 为最终交付目标；LangChain 按需使用。
- 目标用户主要使用手机还是电脑；是否加入登录或跨设备任务历史，当前凭任务访问凭证恢复不依赖账号系统。
- LLM 供应商、型号、预算、结构化调用效果与持久化后端兼容版本。
- 首版视频大小与时长上限、保留时长、服务器磁盘及并发能力。
- 现有引擎仓库、模型权重及使用许可；目标视频样本和算力。
- 固定机位篮筐定位成功率、处理耗时和浏览器编码兼容性。
