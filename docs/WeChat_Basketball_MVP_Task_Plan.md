# 篮球剪辑 Agent：聊天式最小闭环任务计划

版本：v0.5
日期：2026-11-26
用途：当前唯一有效的首版范围与验收依据，取代 v0.3 中过大的交付范围。

## 1. 最终交付目标

交付一个 React 聊天页面和基于 LangGraph + LLM 的篮球剪辑 Agent。用户进入页面收到自我介绍与操作引导，在聊天中上传短视频，Agent 自动生成可靠进球集锦；用户可继续输入少量剪辑指令，系统复用识别结果重新生成集锦，在同一聊天中播放和下载。

核心验收：欢迎介绍 → 上传视频 → 状态消息 → 自动集锦 → 输入“去掉第二球，每球前面多留三秒” → Agent 说明理解后的修改 → 生成新版并播放下载。验证排除正确、相对时长正确、边界正确，且不重新识别。

首版面向本地或小范围受控试用，固定机位、单个清晰篮筐、短视频。真实识别效果和性能通过样本记录，不预先承诺准确率、整场录像或数 GB 上传。

## 2. 聊天界面与首次引导

页面以单个聊天会话为核心：消息区、视频上传入口、文字输入框、发送按钮和快捷指令。上传进度、处理阶段、错误和结果卡片均在聊天内展示；不建设仪表盘、独立任务管理页或专业编辑器。

打开新会话时立即显示固定欢迎消息，无需等待 LLM：

> 你好，我是篮球进球剪辑助手。我可以从固定机位、篮筐清晰的篮球视频中寻找可靠进球，生成可播放、下载的集锦。请先点击下方按钮上传一段短视频。默认每球保留前 5 秒、后 2 秒。生成后，你可以说：“每球前面改成 8 秒”“每球后面多留 1 秒”“去掉第二球”或“查看进度”。识别不清楚的球不会自动加入集锦。

欢迎卡片展示当前服务端配置的格式、大小及时长限制，上传按钮始终可见。未上传时收到剪辑要求，Agent 提示先上传，不能假装开始处理。快捷指令可填入输入框，涉及具体事件的操作在结果生成后才可执行。

前端设计参考 `frontend-design` skill：实施前由前端 Agent 查找并阅读其 SKILL.md，结合本项目的篮球剪辑聊天场景确定排版、配色、间距与交互细节。设计覆盖欢迎介绍、上传、处理中、结果、修改与错误状态，保持统一视觉层级，兼顾手机和桌面、键盘操作与文字可读性；设计工作不扩大最小闭环功能范围。前端实施已读取公开来源 `https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md`，排版、配色、间距等设计 tokens 记录在 `frontend/DESIGN.md`；这不表示全局安装该 skill。

首次收到视频后回复“已收到，正在检查视频”，之后根据真实状态展示分析、剪辑和完成；不编造百分比或预计完成时间。完成卡片包含播放器、下载按钮和按时间排序的进球编号/时间点，方便用户引用“第二球”。

## 3. 最小支持指令与行为

- “查看进度”：查询真实任务阶段。
- “每球前面改成 8 秒”：绝对设置前置时长；后置时长同理。
- “每球前面多留 3 秒”：相对增加时长；后置时长同理。
- “去掉第二球”：排除当前结果事件列表的第二个进球。
- 一句话组合上述修改，例如核心验收指令。

不明确的指令在聊天中澄清；未支持的球员筛选、字幕、配乐等操作明确说明暂不支持。LLM 将指令转换为受校验的结构化操作，不能直接执行 shell 或任意 FFmpeg 命令。

明确指令直接执行并说明修改，无需每次额外确认。同一请求重复提交不能重复增加时长。处理期间仅允许查询进度，不并发修改同一视频，输入框给出提示。首版一个会话只处理一个视频；开始新视频前明确提示会重置当前上下文，不做多视频混合剪辑。

## 4. 技术与最小后端

| 模块 | 技术与范围 |
|---|---|
| 前端 | React + TypeScript + Vite；单页聊天、上传进度、状态消息、结果卡片 |
| API | Python + FastAPI；仅上传、消息提交、任务/消息查询、受控结果访问 |
| Agent | LangGraph + 支持结构化输出/工具调用的 LLM；理解、澄清、分析、方案更新、渲染 |
| 执行 | 一个独立 Python worker；SQLite 任务表串行领取，单任务执行 |
| 数据 | SQLite 保存任务、消息、事件和当前剪辑参数；本地独立任务目录保存视频与成片 |
| 识别 | 复用 baketball_detect 分支的现有引擎；保留原始判断与证据 |
| 剪辑 | FFprobe + FFmpeg；从原片生成浏览器可播放的 MP4 |

LangChain 按需使用。LLM 供应商/型号通过服务端配置选择，密钥不进入前端。欢迎和固定状态消息不调用模型；进度查询无需 LLM 即可完成。默认模型只接收文本与事件元数据，不上传原视频给第三方模型。

后台任务不占用上传/消息请求。SQLite 保存 queued 状态，worker 串行执行；不用 Redis、Celery、独立数据库服务、复杂租约平台或多 worker 调度。服务启动时将遗留 running 任务明确标为 interrupted，提示重新提交，不承诺断点续算。worker 设置处理超时；不建设通用自动重试系统。

会话消息、当前方案和结果引用持久化，同浏览器刷新后凭任务凭证恢复。不要求 LangGraph 检查点、人工 interrupt、跨进程图恢复；图按持久化业务数据重新启动一次请求的流程即可。

## 5. 识别、修改与结果规则

先整合现有 baketball_detect，核实权重、路径、依赖和许可。现有整片标注输出不等于集锦，需封装事件分析和新增片段导出。

默认纳入确认进球和高可信疑似进球；聊天中展示确认、疑似和不确定候选，提供原片时间点预览和勾选按钮。用户可选择任意非明确未进事件生成集锦，无需 LLM；选择只影响剪辑，不把不确定事件改标为确认。未选事件不纳入本次成片。无可靠进球、无法定位篮筐、损坏或不支持视频返回明确消息，不生成空成片。

默认每球前 5 秒、后 2 秒；校验参数范围，裁剪到原片有效范围，合并重叠区间，按源时间排序。事件有稳定 ID；“第二球”按当前聊天展示的事件列表解释，不按合并后的片段计数。

修改只更新当前方案并重新渲染，复用原片和分析事件。暂不建设版本浏览、回滚或完整版本库；新结果成功前保留上一份有效成片，新版失败时仍能下载上一份。输出使用不同文件名避免缓存混淆和写入半成品，验证完成后再更新当前结果引用。

## 6. 最小保护与后置范围

保留任务级随机访问凭证，服务端保存其哈希；状态、消息、修改、播放和下载都需校验。文件不公开映射，凭证和模型密钥不写日志。不做注册、登录、短信、OAuth、角色体系或跨设备历史。

只做基本输入格式/大小/时长校验、参数校验和单任务串行限制。配置简单保留期，用一个清理函数/脚本删除到期任务及文件，跳过运行中任务；不建立独立清理服务、资源配额平台或成本仪表盘。

明确后置：专业审核后台、持久化图检查点与断点恢复、多会话管理、跨设备历史、方案版本界面、并发编辑、自动重试平台、分块续传、对象存储、数 GB 录像、微服务拆分、微信接入、球员识别、字幕和配乐。生产部署与运维扩展不作为本轮前置条件。

## 7. 任务与交付顺序

| 步骤 | 工作 | 验收 |
|---|---|---|
| S0 | 整合识别分支，约定消息/事件/方案/结果接口 | 原测试可运行；样本与真实效果限制有记录 |
| S1 | 聊天页面与上传、最小任务存储 | 新会话立即自我介绍、引导上传、展示指令；上传有进度，刷新恢复 |
| S2 | worker 调用识别与 FFmpeg | 自动集锦在聊天内播放下载；错误清楚；请求不等待识别结束 |
| S3 | LangGraph + LLM 指令处理 | 时长调整、删除事件、澄清和组合指令正确；修改不重新识别 |
| S4 | 最小端到端验收与使用说明 | 核心场景通过，凭证隔离有效，失败保留旧成片 |

固定前十秒剪辑和原样交付可作为内部调试，不是独立产品里程碑。最终交付以 S4 聊天最小闭环为准，旧版 M4 的候选审核与复杂恢复要求不再适用。

## 8. 验收检查

- 新会话不依赖模型即可显示介绍、能力边界、上传入口和可用指令。
- 未上传先发指令、上传超限/损坏文件、无篮筐、无进球均有明确聊天反馈。
- 真实视频完成分析、集锦播放和下载；记录样本、设备、误检漏检和耗时。
- 核心组合指令正确；相对/绝对时长区分正确，重复请求不重复累加。
- 修改时分析调用次数不增加；重叠区间和原片首尾处理正确。
- 模型或渲染失败有可见反馈，不覆盖已有可用结果；不支持指令不执行。
- 刷新恢复同一会话；服务重启后的运行中任务明确中断，不假报成功。
- 不同任务凭证不能读取或修改彼此消息和文件；到期内容不可访问。
